# Vision & Scope

상태: 현행 목적·범위 / 최초 작성 2026-10-14, 문서 분류 확인 2026-10-15

## 왜 만드는가

`leeeeeoy.xyz`를 특정 직업이나 이직 준비를 위한 결과물로 제한하지 않고, 한 개인이 살아가며 경험하고 배우고 생각한 것을 누적하는 **개인 웹사이트**로 운영한다.

### 세 가지 핵심 공간

- **Portfolio:** 지금까지의 경력·프로젝트·검증된 실무 문제 해결을 소개한다. 사이트 자체의 목적이 아니다.
- **Lab:** 기술적 궁금증, 가설, 학습, 코드 실험, 측정 결과를 남긴다. 실험하지 않은 이론 메모도 허용한다.
- **Writing:** 일상, 회고, 감상, 생각을 형식 제한 없이 기록한다. 기술적 검증 서술을 강제하지 않는다.

Home은 공간의 입구로서 간단 소개와 Portfolio/Lab/Writing으로 가는 링크를 제공한다. 최근 글/실험 링크는 실제 공개 콘텐츠가 있을 때 검토한다. 독립 About 페이지는 현 단계 필수가 아니다. 콘텐츠 분류는 최초 위 두 글 영역으로 시작하고 실제 기록이 쌓인 후 확장한다.

## 지금 구현할 것

1. 기존 포트폴리오의 콘텐츠·접근성·테마·배포 동작을 유지한다.
2. 웹에 Portfolio, Lab, Writing을 탐색할 수 있는 경로와 표시 기능을 둔다.
3. Lab·Writing 콘텐츠를 Markdown 기반 정적 파일로 관리한다.
4. 실행 가능한 실험을 `labs/` 아래 **독립 프로젝트**로 둔다.
5. 에이전트가 문서를 탐색하고 변경을 검증할 수 있도록 최소 문서·테스트 구조를 정리한다.

## 하지 않을 것(이번 범위 제외)

- 로그인, 회원, 소셜 인증, 댓글, 좋아요, 알림, CMS, 관리자 페이지
- 새 서버·DB·스토리지 시스템 구축, D1/Worker 삭제, 결제/후원
- 기술 글과 개인 글을 강제로 동일한 목차·양식으로 통일
- SEO만을 이유로 한 프레임워크 전체 재작성
- 모든 실험 결과의 웹 자동 발행, 모든 실험에 공통 런타임 도입
- 기존 포트폴리오 경력 서술의 무근거 수정 또는 이력서 원문 수입

## 설계 판단 원칙

1. **기록을 남기는 비용이 낮을 것**: Markdown 작성 → 빌드 → 발행.
2. **검증 가능한 것과 주관적인 것을 구분**: Lab은 증거/한계, Writing은 개인 표현의 자유.
3. **기존 작동 기능을 잃지 않을 것**: 작게 이전하고 회귀 검증.
4. **추상화보다 실제 필요**: 콘텐츠·실험이 아직 적으므로 가장 단순한 구현 선택.
5. **공개 의도 명확화**: Public Git의 초안은 웹에서 숨겨도 공개된다.
