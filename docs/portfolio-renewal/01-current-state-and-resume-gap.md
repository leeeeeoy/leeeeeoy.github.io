# 현재 상태와 이력서 차이

## 분석 기준

- 2026-07-28에 저장된 4페이지 PDF 이력서 4종
- 운영 API의 profile, careers, projects, skills 응답
- 현재 Flutter Web의 홈, 경력, 프로젝트, 스킬 화면
- Cloudflare Pages, Workers, D1, R2 실제 설정

네 이력서는 지원 역할별 강조점이 다르다. 포트폴리오에는 특정 지원 기업을 위한 지원 동기나
표현을 옮기지 않고, 여러 문서에서 반복되고 수치 근거가 있는 공통 사실만 반영한다.

## 공통 경력 서사

현재 이력서에서 반복되는 핵심은 다음 다섯 가지다.

1. Flutter 기반 Android·iOS 서비스 설계, 출시, 운영
2. 인수인계가 부족한 레거시 분석과 점진적 아키텍처 전환
3. DevTools와 운영 지표를 이용한 메모리·OOM 개선
4. MethodChannel, WebView, WebSocket을 이용한 외부 시스템 연동
5. GitHub Actions, SonarQube, Patrol, Fastlane을 이용한 품질·배포 자동화

현재 포트폴리오 소개는 구조 단순화에 집중되어 있어 2번은 잘 드러나지만,
3~5번의 실측 결과와 운영 역량은 첫 화면에서 충분히 드러나지 않는다.

## 현재 데이터에서 유지할 내용

### 경력

- 세 회사의 근무 순서와 기간
- 비상장 주식 앱의 사용자 규모와 메모리 약 20% 개선
- 아파트 관리 서비스의 모바일·웹 운영 경험
- 현재 회사에서의 1인 모바일 개발 및 예약 데이터 통합
- Bloc 중심의 점진적 구조 개선

### 사이드 프로젝트

- 반려견 숏폼 서비스의 운영 규모와 OOM 약 90% 개선
- 타이머 앱의 Live Activity·MethodChannel 구현
- 지도 서비스의 위치 기반 기능과 API debounce

### 인프라

- Pages, Workers, D1, R2의 실제 운영 경험
- 변경 영역별 독립 배포

| 현재 회사 | 모바일과 백엔드 기여가 별도 상세 항목 | 한 경력 안에서 역할과 성과로 통합 |

| BPP | 메인 프로젝트로 노출 | 최근 이력서에서 제외되므로 archive 또는 제거 |
| 스킬 퍼센트 | Flutter 90, Go 50 등 | 근거 없는 숙련도 숫자를 제거하고 사용 맥락으로 표시 |
| 지역 | 상세 구 단위 공개 | `Seoul, Korea` 수준으로 축소 |

## 문서 간 확인이 필요한 불일치

게시 전 당사자 확인이 필요하다.

- 현재 서비스 등록 사용자: `4,000~5,000` 또는 `5,000+`
- 현재 서비스 MAU 공개 여부
- 배포 시간 단축: `최소 20분` 또는 `30분 이상`
- HRV 기능의 최종 운영 구현: Native Camera/ML Kit 또는 WebView 측정 모듈
- 심리검사, 결제, 키오스크, React 예약 웹 중 공개 가능한 범위
- 현 직장 프로젝트 상세 종료일이 있는 문서와 “재직 중” 표현의 관계
- Go를 현재 핵심 스킬로 계속 노출할 근거
- AI 도구 활용을 핵심 역량으로 공개할지 여부

확정 전에는 범위가 더 보수적인 표현을 사용한다.

## 제거 또는 축소할 기능

- 내용이 없는 `/profile` 라우트
- 근거 없는 스킬 진행률 그래프
- 긴 작업 목록을 그대로 나열하는 카드
- 모든 이미지를 큰 carousel로 표시하는 구조
- 원시 네트워크 오류 문자열 노출
- 구현 스택을 설명하는 큰 모달

새 포트폴리오 자체의 기술 설명은 footer 또는 작은 `Built with` 링크로 충분하다.
