# Content & Publishing Guide

상태: Phase 3용 제안. 현재 `content/`는 디렉터리만 마련했고 렌더링·발행 기능은 구현하지 않았다.

목적: 공통 렌더링 규칙은 간단히, Lab과 Writing의 글쓰기 방식은 자유롭게.

## Lab — 탐구·이론·실험

- 기술적으로 궁금한 질문, 학습한 개념, 직접 검증한 결과를 담는다.
- **실험 글:** 질문 → 가설 → 환경과 절차 → 실제 결과 → 해석 → 한계/후속 질문.
- **이론/학습 노트:** 무엇을 이해하려 했는지, 공식·1차 문서와 예제, 내 이해의 한계 중심.
- 실험 전 반드시 '예상 결과'와 '실측 결과'를 분리한다. LLM이 생성한 예시 수치를 실측으로 쓰지 않는다.
- 정확도가 중요한 주장에는 문서 링크 또는 결과 파일/커밋을 연결한다. 블로그 글과 코드 저장소는 1:1 대응을 강제하지 않는다.
- 실험의 재현성과 코드는 `labs/<name>/README.md`로부터 접근 가능해야 한다.

## Writing — 생활·회고·생각

- 일상·경험·회고·감정·취향 등 주제에 제한을 두지 않는다.
- 일정한 문단 구성이나 근거 인용을 강제하지 않는다. 기술적 사실을 주장할 때에만 검증 원칙을 적용한다.
- 사생활, 주변 인물, 직장 정보는 공개로 전환하기 전 작성자 본인이 검토한다.
- 글의 미발행 상태와 개인 프라이버시는 별개다. 비공개/민감한 초안은 Public repo에 두지 않는다.

## 콘텐츠 메타데이터

- Markdown 본문은 `content/lab/` 또는 `content/writing/`에 위치.
- 필수 권장: `title`, `date`, `summary`, `draft`; 선택: `tags`, `updated`, `relatedLab` 등 실제 사용 시에만 추가.
- 경로는 카테고리 디렉터리 + slug로 결정. 파일명/필드 방식, 중복의 영역 범위, draft 필수 여부·기본값은 [02의 제안](02-target-architecture.md)과 함께 구현 전 확정한다.
- `draft: true` 항목은 웹 목록·상세·sitemap 및 dist 콘텐츠 출력에서 제외하되, 공개 GitHub의 파일은 공개됨을 UI/문서에 명확히 한다.
- 링크 유효성, 이미지 대체 텍스트, 코드 블록 언어 표기, 표의 모바일 가독성 검증.
- 자유로운 Markdown은 허용하되 임의 스크립트/HTML 삽입을 허용하는 기능은 별도 검토.

## 글 발행 순서

1. 작성: Markdown(공개 가능한 내용만)
2. 검토: 사실/근거 또는 공개 범위/민감 정보
3. Preview: 모바일/데스크톱 및 `?lang=en` 동작, 링크/이미지/코드 렌더링
4. 게시: `draft: false`, PR/CI 통과 후 main 병합
5. 사후: 실제 URL 확인. 필요한 경우 sitemap·메타데이터 갱신

### 콘텐츠 유형별 템플릿

- 실험 보고서: `templates/experiment.md`
- 실험 없는 기술 노트: `templates/lab-note.md`
- 개인 글: `templates/writing.md`

**문장 톤은 작성자 개인의 선택**이다. 에이전트는 사실 확인이나 구조를 도울 수 있지만 주장/경험을 임의로 만들어서는 안 된다.
